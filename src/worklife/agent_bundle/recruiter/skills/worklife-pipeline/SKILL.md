# Отклики, переписка и доступ

Прочитай `agency_brief`, действия из `recruiter_start`, существующие отклики через `records_list("application")` и нужные сообщения через `conversation_list(job_id,limit)`. Проверь реальную вакансию, CV, адресата/ветку и блокировку компании. Для `pipeline_update(job_id,stage,cv_id,note,next_action,due_at)` CV до выбора необязателен. Стадии: `saved`, `applied`, `reply`, `interview`, `offer`, `accepted`, `rejected`, `withdrawn`. Запись стадии не отправляет отклик, не бронирует встречу и не принимает оффер.

## Внешнее действие

Подготовь конкретный текст и вложения на основе фактов. Используй имеющийся явный мандат; если отправка или регистрация в него не входит, запроси только недостающее разрешение после подготовки. Не превращай разрешение составить письмо в разрешение отправить его.

1. `action_draft(connector,operation,payload,idempotency_key)` сохраняет действие. Ключ соответствует одному намерению; при повторном вызове после сбоя не создавай новый ключ ради обхода проверки.
2. Укажи `_job_id` либо `_employer_domain` для контакта с работодателем. Email `send`: `to,subject,body,attachments,in_reply_to`; HH `apply`: `vacancy_id,resume_id,message`, HH `reply`: `negotiation_id,message`; Telegram `send`: `chat_id,text`. HTTP использует объявленную операцию настроенного адаптера. Имена каналов и доступные операции проверь через `connectors_list`.
3. При наличии разрешения вызови `action_approve(action_id)`, затем `action_execute(action_id)`. Прочитай фактический статус и квитанцию. Квитанция провайдера подтверждает отправку в её пределах, не ответ работодателя и не получение оффера.
4. Если доставка `uncertain` или `sending`, сначала проверь провайдера/ветку. Используй `action_reconcile(action_id,delivered,evidence)` только с найденным свидетельством. Не отправляй повторно «на всякий случай». Неисполненный черновик можно отменить через `action_cancel`.

В браузере сначала `browser_open`/`browser_inspect`, затем при необходимости `browser_prepare` для заполнения, выбора или загрузки. Формы могут сохраняться автоматически — учитывай это в разрешении. Нажатия идут через действие с `connector="browser"`, операцией `click`/`press`, `selector`, `expected_url` и, для press, `key`. После каждого нажатия проверь фактический результат; переход на страницу не равен отправке формы.

## Входящие и следующие шаги

`inbox_sync(connector,operation,parameters,job_id,limit)` читает и сохраняет сообщения. Продолжай пагинацию по возвращённым параметрам; расписание сохраняет курсор после завершённого чтения. Передавай `job_id` лишь при доказанной связи с конкретной вакансией, не для всего общего почтового ящика. Сходство темы, имени или компании не является точной связью.

Для ручного наблюдения используй `conversation_record(job_id,direction,channel,text,external_id,in_reply_to,occurred_at,status)`. Направление: `inbound`, `outbound`, `unknown`; неизвестная вакансия: `job_id=null`. Сохраняй provider IDs и точный `in_reply_to`; у HH это ID в конкретной negotiation, у Telegram — в конкретном chat. Не превращай квитанцию отправки или исходящий текст во входящий ответ. Статус `observed`, `received` или `read` у известного входящего может автоматически перевести `saved/applied` в `reply`; это ещё не положительный ответ. Проверь содержание перед дальнейшей сменой стадии. Молчание не означает отказ.

Запиши наблюдаемую стадию и следующий шаг с `due_at` в ISO-формате с часовым поясом. Не помечай просроченный follow-up выполненным только потому, что прочитал напоминание.

Если связь ранее не была установлена, проверь содержание и задай её явно через `conversation_update(message_id,job_id=...)`. `unlink=True` снимает ошибочную связь; без этих параметров она остаётся прежней. `read=True` отмечает сообщение прочитанным только в Worklife; это не отправляет квитанцию провайдеру и не меняет исходное содержание. Не связывай сообщение по одному сходству имени компании.

## Новый аккаунт

При разрешённой регистрации сохрани платформу через `platform_save`, создай ссылку `credential_create(name,username)`, заполняй пароль через `browser_fill_credential(selector,name,field)`. Читай код/ссылку подтверждения через настроенный канал в рамках этой регистрации. Сохраняй в `account_save(platform_id,identifier,status,email,notes)` только метаданные и ссылку credential; `active` ставь после реального подтверждения. Не записывай пароль, токен или тело письма подтверждения в notes. Если доступ/CAPTCHA требует человека, сохрани точный незавершённый шаг.
