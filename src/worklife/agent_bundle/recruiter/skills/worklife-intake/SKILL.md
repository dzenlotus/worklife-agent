# Цели и рабочий мандат

Прочитай `recruiter_start` и `agency_brief`. Выдели уже известное, последнее поручение, ближайшие обязательства и только те пробелы, которые меняют следующий выбор. Не выводи целевую профессию из прошлой должности; не навязывай Git-анализ человеку другой профессии.

Сохраняй в профиле явные `target_roles`, `target_locations`, `languages`, `income_deadline` и `life_preferences`. `income_deadline` — дата первого поступления денег, не дата выхода. Используй формат `YYYY-MM-DD` либо ISO-время с часовым поясом. Уточни жёсткость ограничений, если она влияет на отбор; не объявляй пожелание запретом самостоятельно.

`profile_save(profile)` заменяет весь объект. Сначала возьми текущий профиль из `recruiter_start`, затем объедини изменения с ним, сохрани прежние факты и неизвестные тебе поля. Доказательства: `facts=[{id,text,source}]` с уникальными стабильными ID. Текст пользователя — собственное утверждение пользователя; источник из резюме не становится независимой проверкой. Для импорта резюме загрузи `worklife-match-cv` через `recruiter_skill` или соседний `SKILL.md`.

Числовые условия хранятся в `constraints`: `remote`, `min_salary`, `currency`, `salary_period`, `salary_gross`, `max_hours`, `max_hiring_stages`, `max_test_hours`. Для минимального дохода нужны сумма, валюта, период и база до/после налогов. `salary_gross=true` означает до налогов, `false` — после. Не подставляй страну, валюту, регион или доход по умолчанию. Дополнительные жизненные условия сохрани словами и проверяй сам: наличие поля не гарантирует автоматическую оценку.

Проверь `connectors_list`, существующие `platform`, `account`, `resource`, `schedule` через `records_list`. Пользователь не должен вручную заводить учётные записи в Worklife: сам сохраняй обнаруженные платформы и фактический статус доступа. Для настройки адаптера используй `connector_configure` только с поддержанным типом и ссылками `*_env`/`headers_env` на секреты. Отсутствующий доступ запроси, не выдавая план регистрации за выполненную регистрацию.

Согласованный мандат можно сохранить частно через `research_note(title,hypothesis,evidence,next_step)`: явно опиши границы внешних действий, источники разрешения и условия остановки. Это памятка о реальном поручении, а не способ выдать себе полномочия. Не расширяй прежнее разрешение на другие аккаунты, получателей или публикации.

Заверши ближайшим исполнимым шагом. При разрешённом поиске переходи к `worklife-market`; при отложенном поиске подготовь профиль/CV и зафиксируй недостающие входные данные без реальных запросов к площадкам.
