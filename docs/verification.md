# Проверка Worklife — 27 октября 2026

Проверено на macOS arm64, Python 3.12.12. Установлены зависимости из `uv.lock`,
MCP Python SDK 1.30.0 и Chromium Playwright. Внешние письма и сообщения не отправлялись.

## Автоматические проверки

`uv run pytest -q`: **20 passed**.

| Проверка | Подтверждено |
|---|---|
| Личный сценарий | Профиль → варианты CV из существующих фактов → оценка вакансии → стадии отклика → гипотеза/назначение/результат/follow-up |
| Условия жизни | Удалёнка, зарплатные единицы, gross/net, неизвестные условия; несовместимая вакансия отклоняется |
| Отправки | Черновик не отправляется, требуется authorized-состояние; повтор sent не вызывает провайдера; timeout → uncertain без автоматического повтора |
| Почта | MIME-вложение и In-Reply-To; реальная SMTP-доставка в локальный тестовый сервер |
| API | HH/Greenhouse/Lever через локальные HTTP fixtures; универсальные read/write методы, параметры пути и тело запроса |
| Секреты | Конфигурация ссылается на переменные окружения; status показывает имена/наличие, не значения, включая заголовки API |
| MCP | Отдельный stdio-процесс, настоящий ClientSession, initialize/list_tools/call_tool |
| Браузер | Настоящий Chromium: страница → ввод → загрузка файла → клик → проверка результата; генерация PDF |
| Репликация | Двусторонняя синхронизация двух узлов по настоящему localhost HTTP; повторная синхронизация; проверка identity; перезапуск сохраняет данные |
| Транзитивный обмен | Подписанная запись проходит A → B → C, сохраняет автора и подпись |
| Подмена | Изменённая запись отвергается; пакет с подделкой не импортируется частично |
| Локальная порча | Проверяются и подписанный JSON, и индексные столбцы; обычный запрос не выдаёт поддельный локальный отзыв |
| Развилка автора | Две ветки одного ключа/номера обнаруживаются и не сливаются молча |
| Исправление/отзыв | Только собственная запись автора; исходная история сохраняется |
| Эксперименты | Неподанные заявки исключены из знаменателя, поздние ответы не меняют фиксированную метрику, мало данных → insufficient_data |
| Backup | Восстановлены авторский ключ, личный профиль и проверяемый общий журнал |
| CLI | Рабочее демо и вызов MCP-инструмента через JSON CLI |

`uv run ruff check src tests`: успешно. `uv run ruff format --check src tests`: успешно.
Есть одно предупреждение DeprecationWarning внутри установленной Starlette о совместимости alias AnyIO;
оно не вызвано кодом проекта и не меняет результаты.

## Ручные проверки поставки

- `uv build`: собраны wheel и sdist.
- Собранный wheel установлен через изолированный `uv tool run`; CLI `init` отработал.
- Проверено содержимое wheel/sdist: в них нет identity.key, личной `.env`, `config.toml`, `.venv` и тестовых артефактов.
- `worklife --home artifacts/demo demo`: создана вторая локальная копия; `tampering_rejected=true`.
- `cv_export` через CLI создал файл `artifacts/demo-cv.pdf`.
- `worker --once`: отработал, записал статус; реальные peers ещё не настроены.
- Конфигурация `examples/mcp.local.json` проверена настоящим MCP-клиентом, включая `agent_brief` с полным config.toml.

## Живые API

Read-only запросы выполнены установленным кодом адаптеров:

- **Greenhouse:** получены 18 вакансий board `greenhouse`, включая реальные названия и ссылки.
- **Lever:** получены 2 вакансии board `palantir` с `limit=2`.
- **HH:** HTTP 403; доступ не подтверждён. Нужны корректные разрешения/регистрация приложения и проверка из среды владельца.

Снимок результата чтения находится локально в `artifacts/live-read-results.json`;
источники меняются, эти количества не являются обещанием будущей выдачи.

## Что не проверено во внешней среде

- Реальные SMTP/IMAP-аккаунты, Telegram, Slack, Brave и HH-отправки: пользовательские credentials не предоставлены.
- Реальная подача заявления, ответы рекрутеров, доставка письма адресату и улучшение скорости трудоустройства.
- Размещение на нескольких независимых машинах/владельцах, TLS/DNS и восстановление после реальной аварии инфраструктуры.
- Docker build/run: установлен клиент Docker, но daemon недоступен. Dockerfile/compose предоставлены без заявления о runtime-проверке.
- Масштабная публичная сеть, защита от Sybil/DoS, управление общим консенсусом и ротация скомпрометированных ключей.

Поставлен рабочий локальный инструмент и протокол обмена. Для эксплуатации нужно подключить реальные аккаунты,
назначить расписание агенту в его harness и разместить независимые реплики/backup.
