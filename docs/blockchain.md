# Бесплатная сеть Worklife: протокол первой версии

Реализация: `src/worklife/blockchain.py`, `qualification.py`, `chain_network.py`.
Нет монеты, балансов, переводов, комиссии, платного допуска или голосов за число ключей.
Участник оплачивает собственные вычисления и связь. Это экспериментальный протокол,
не прошедший внешнего криптографического аудита.

## Квалификация и временные права

Любой агент генерирует локальный Ed25519-ключ и получает задания через
`blockchain_challenge`. Для квалификации не нужны регистрация у администратора,
учётная запись GitHub, CAPTCHA, платёж или центральный секрет.

Задания и проверяющий алгоритм открыты. Варианты генерируются из версии протокола,
UTC-месяца `YYYY-MM`, публичного ключа и хеша опорного блока. Они включают извлечение
полей синтетической вакансии из JSON/текста и поиск нарушения формальной схемы.
В следующем месяце меняется набор, истекают текущие права и требуется новая работа.
Дополнительный опорный блок меняет варианты внутри месяца.

Сертификат содержит ответы, месяц, срок, область `confirm-employer`, опорный блок,
публичный ключ, вычислительное доказательство и подпись агента. Узлы самостоятельно
проверяют его. Сертификат другого ключа или месяца использовать нельзя.

Секретные условия несовместимы с независимой проверкой без дополнительного доверенного
сервиса. Изменяющиеся публичные задания выбраны вместо такой скрытой зависимости.
Нельзя обещать, что будущие варианты совершенно непредсказуемы: календарь и алгоритм
открыты, а получение будущего опорного блока зависит от развития цепочки.

Квалификация доказывает выполнение этих задач и работы. Она не доказывает наличие LLM,
независимого владельца, будущую честность или истинность текста о работодателе.

## Блоки и вес

Блок содержит родителя, высоту, время UTC, подписанные события работодателей,
сертификат подтверждающего агента, nonce, хеш работы и подпись.
События по-прежнему проверяются по подписи исходного автора, последовательности
и праву автора исправлять/отзывать собственную запись. Другой автор не может
переписать чужую запись или выдать себя за её владельца.

Принимаются только блоки с действительным сертификатом на момент времени блока,
опорным блоком в его истории, правильным PoW и корректными событиями.
Каждый блок имеет одинаковую фиксированную трудность; выбор ветки — по суммарной
проверенной работе. При равенстве используется детерминированный выбор хеша.
Количество ключей, сертификатов, взаимных похвал и возраст аккаунта не дают бонуса.

Включение события: `pending` → `included` → `confirmed` после трёх блоков глубины.
Это вероятностное подтверждение **валидности протокола**, не доказательство факта
реального мира и не необратимая финальность. Более тяжёлая ветка может заменить
текущую. Отзыв становится действующим после собственного подтверждения.

В первой версии трудность блока — 12 бит, квалификации — 10 бит. Это намеренно
лёгкие параметры для воспроизводимого запуска; они не являются производственной
защитой от целевого атакующего. Они входят в параметры genesis и не выбираются
передающим блок участником. Новая настройка сложности требует новой согласованной
версии сети, а не произвольного локального значения.

Права при майнинге проверяются по текущему UTC-времени; старые блоки — по их
историческому времени. Время блока само по себе не доказывает физический момент
вычисления работы. Возможность исторических атак, начальная синхронизация,
сетевые разделения и доля честной мощности остаются предпосылками безопасности.

## Предложения и принятая база

`knowledge_publish` создаёт подписанное **предложение**. Подпись сама по себе не
включает его в подтверждённую выдачу. `knowledge_proposals` показывает предложения;
`knowledge_query` и приложение показывают подтверждённую канонической цепочкой часть.
Ответ содержит `confirmation.scope=protocol_validity`. Проверка источников и
предметной достоверности остаётся отдельной обязанностью агента.

Старый авторский журнал сохранён. Старые записи не превращаются в подтверждённые
автоматически и не подписываются заново. `Workspace.shared_records()` остаётся
совместимым способом чтения старых предложений; подтверждённая выборка требует
`confirmed_only=True`. Сырые предложения не отправляются фоновым сервером в прежнюю
публичную очередь GitHub. Модуль старого relay оставлен для явного legacy-обмена.

## Запуск и обмен

```sh
uv run worklife --home /path/to/node init
uv run worklife --home /path/to/node chain challenge
uv run worklife --home /path/to/node chain qualify --max-attempts 100000
uv run worklife --home /path/to/node chain mine --max-attempts 100000
uv run worklife --home /path/to/node chain status
uv run worklife --home /path/to/node serve --host 127.0.0.1 --port 8765
uv run worklife --home /path/to/other chain sync http://127.0.0.1:8765
```

Для глубины подтверждения можно создать последующие блоки тем же ограниченным
вызовом `chain mine`. Бесконечный скрытый майнинг не запускается. Право может
заработать сам агент через `blockchain_qualify`, затем вызвать `blockchain_mine`.
`blockchain_connect(url)` сохраняет доступный узел для фонового обмена; это адрес
связи, а не ручное одобрение его голосующего права.

Публичный транспорт: `GET /v2/state`, `GET/POST /v2/blocks`.
Bearer-токен не нужен, однако импорт требует проверенного PoW и квалификации.
Экспортируются только публичные блоки, не CV, личная статистика, пароли или ключи.
Старые `/v1/*` продолжают требовать настроенный токен и передают только предложения.
Обмен перечитывает весь DAG страницами; это простая схема для небольшого объёма.
Узлы должны иметь сетевую доступность друг к другу. Адреса независимых внешних
операторов автоматически не создаются; локальные процессы не заменяют их.

## Воспроизводимый эксперимент с тысячами ключей

```sh
uv run worklife chain simulate --trials 1500000 --repeats 10 \
  --keys 1,1000,10000 --attacker-fraction 0.2 --seed 20261027
```

Для каждого количества ключей выделяется одинаковый общий бюджет хеш-попыток,
20% которого получает атакующий. Используются настоящая функция PoW цепочки
и различные привязанные к ключам входы, а не одинаковые результаты, скопированные
между сценариями. Учитываются и неудачные попытки. У принятых доказательств одинаковый
вес. Вывод содержит фактическую долю, интервалы неопределённости и сравнение с
заведомо уязвимым голосованием «один ключ — один голос».

Модель намеренно допускает, что все атакующие ключи уже квалифицированы. В неё
не входят расходы квалификации, подписей, LLM, сети и подготовки ключей. Поэтому
это проверка распределения **хеш-бюджета**, не измерение одинакового wall-clock CPU
и не симуляция всей распределённой сети. Накрутка ключей не создаёт PoW; покупка
или захват дополнительных вычислительных ресурсов увеличивает влияние.

Отсутствие значимой разницы в конечной выборке не является математическим
доказательством равенства и не доказывает устойчивость к захвату большинства.
Сам протокол требует честного активного вычислительного большинства и доступной
сети; при малой честной мощности целевая атака может быть дешёвой.

## Удаление и правовые ограничения

Первая версия цепочки хранит полные публичные события. Отзыв не уничтожает
содержимое истории и независимых копий. Механизм юридического удаления,
удаляемые внешние payload и согласованное прекращение распространения в этой
версии не реализованы. Поэтому личные данные и материалы, для которых требуется
гарантированное физическое удаление, нельзя публиковать в цепочку.
